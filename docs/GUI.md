# 本地桌面界面

双击 macOS 的 `scripts/launch-factory-monitor.command`，或在 Windows PowerShell 执行 `scripts/launch-factory-monitor.ps1`。两者均以 demo 打开；启动窗口本身不读取屏幕、不打开网络连接，也不启动模型。

本地视觉复核模型是另一个显式步骤：macOS 运行 `scripts/start-local-model.command`，Windows 运行 `scripts/start-local-model.ps1`。它们只会尝试项目内的 Ollama 程序和 `models/ollama`，绑定 `127.0.0.1:11435`，并设置 `OLLAMA_NO_CLOUD=1`；不会自动下载、安装或在启动界面时后台运行。模型未启动或不可用时，先用 `factory-monitor preflight --config config.json --data-dir data` 查看本地状态，界面将事件留给人工复核。

顶部模式标识必须被视为状态证据：`SYNTHETIC / DEMO` 代表脚本化演示，`本地视频回放` 代表离线文件，`本地 live 捕获` 只代表本机尝试，均不构成现场准确率、相机身份或生产验收。

## 校准与配置

停止运行后，选择捕获后端，填写本地监控客户端的精确标题（或明确选择 `display`），再填写预期原生像素宽高和十个可见摄像头 ID 的归一化裁剪 `x,y,w,h`。最后必须主动勾选“逐项确认”才会把布局保存为本地校准；仅填尺寸、裁剪、ROI 或排班不会宣称校准，也不会修改原有已校准布局。保存通过核心配置验证并进行原子写入。宽高为零、裁剪不完整、无明确目标或未确认时，live 启动会被阻止。已保存的布局仍只是本地布局版本，不能说明裁剪对应真实相机。

从摄像头表中选择一行后，可先加载本地静态预览图，在图上点击绘制物料区域、工位区域与两点出入口线，编辑工作日、工作/休息时间和离岗阈值。预览图只帮助人工布局，不是对现场相机身份的证明。区域与排班会写入同一次保存。平面图可以导入本地图片；选择摄像头 ID 后点击平面图即可放置点位，朝向和相关摄像头 ID 在表中编辑。点击点位会要求运行时切换视角，未经切换校准时应显示拒绝原因。

若需要为本地切换读回准备身份资料，先导入停止状态的本地截图，选择摄像头 ID 和 `grid` 或 `detail` 截图类型，填写截图中固定可见的摄像头编号/名称，并填写紧贴该编号/名称的归一化矩形 `x,y,w,h`。点击“记录本地模板并保存”会将这个小区域保存到 `data/calibration_templates`，并在配置中记录其最小相似度、区分度和预期标签。整个场景、人物或运动区域不可以作为身份模板；空白或低纹理区域会被拒绝。十个网格和十个详情模板齐全也只表示资料齐全，运行时仍必须进行本地读回并拒绝相同、模糊或错配标签。修改窗口目标、后端、像素尺寸或任何摄像头裁剪会清空这些身份资料，并要求重新确认。

运行后，十个预览格只显示运行时提供的帧和健康状态。捕获权限、模型缺失、视频读失败、布局失效与证据缺失都会写进本地诊断区；界面不会用假检测替代这些错误。新候选、`uncertain`、`timeout` 和 `error` 状态会以黄色候选标记、桌面通知和提示音请求人工复核，绝不构成对人的指控。候选事件可以标记“人工确认”或“误报”，标签写进本地 SQLite 事件库。

选择事件会显示规则原因、分析状态、录制状态和证据时间轴缺口。缺口可能是旧格式的时间对，也可能带有 `start`、`end`、`reason`；未知结束时间表示覆盖不完整。只有存在的本地预览/证据文件才可点击“用系统打开本地证据”。此按钮仅向操作系统请求打开文件，不声明本机 codec 已成功播放；缺失或不完整证据会保持明确可见。停止时可以把“本地复核服务地址”保存为 `http://127.0.0.1:11435`，与项目内本地模型脚本对应。

## 打包

`scripts/build-macos.command` 使用当前 macOS 的 `.venv` 生成 wheel/sdist。`scripts/build-windows.ps1` 必须在 Windows 上执行；它是面向 Windows 的启动说明和本地构建脚本，尚未在 Windows 机器上验证，不能视为跨平台构建证据。
