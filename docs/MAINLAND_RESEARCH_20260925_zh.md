# 十路监控本地视觉提示系统：独立架构与资源核查

核查日期：2026-09-25。只读研究；未安装模型、下载权重、发送监控媒体或修改主工程。

## 结论给主控

建议把新购设备的首选验证路线定为 **Windows + NVIDIA 16GB 显存卡（优先 RTX 5060 Ti 16GB）+ Qwen3-VL-2B-Instruct 作为事件复核候选**。前置检测、节流和十路状态仍由轻量确定性视觉/运动检测承担；只有触发事件才把带时间戳的少量相邻帧或事件片段送到本地 VLM，结果先成为人工复核提示。现有主工程指定 Windows WGC 和 macOS ScreenCaptureKit 屏幕采集；如果当前只能用 Mac，可继续采集/UI 验证，但模型在 Apple/MPS 上的依赖、显存压力和目标延迟需要单独现场实测，不能把 Qwen CUDA 用例直接当 Mac 性能证据。

这是候选架构，不是十路验收结论。官方仓库展示的单图/视频调用、参数量或单卡基准都没有证明真实 Seetong 画面在十路负载下能于 15 秒内可靠告警。Laya 与本地视觉链路无关，不应进入图像推理路径。

## 推荐的数据流与边界

`10 路本地屏幕采集（WGC） → 每路时间戳/轻量运动或人员候选检测 → 每路有界事件队列和原始证据环形缓存 → 单张 RTX 上的本地 VLM 复核（只处理候选、抽样关键帧/ROI） → 有证据片段、摄像头匿名 ID、时间戳、模型输出与超时原因的提示 → 人工确认`

GPU 复核服务应有全局并发上限、每路公平调度、截止时间、队列长度上限和显式超时/丢弃记账；任何未处理完、截断、低置信度或超时事件均保持“待人工看”，不能变成“无异常”。屏幕总览保证的是预览采集覆盖，不代表每个小窗的空间细节足以识别细动作。采集切图、模型抽帧、原始录像和模型输出需要共用时间戳，并能回放核对。

## 已证实、推断和必须实测

**已证实：** VLX-Seek 1.5 当前公开运行代码/权重只有 10B；单图入口；Laya 是文本决策引擎；Qwen3-VL 提供 2B 权重和视频帧接口；RTX 4060 有 8GB、5060 Ti 有 16GB 版本；官方 GPU 规格与近期大陆零售页面如上。

**推断：** Windows + NVIDIA CUDA 比当前的 Mac 更适合作为新购推理主机，因为主工程已有 Windows WGC 路线，Qwen/VLX 的常见推理栈面向 PyTorch/CUDA；“ModelScope 适合国内预置”仅由官方链接到 ModelScope 推得，没实测无 VPN 下载、完整离线安装或无外联运行。

**必须实测：** 10 路真实画面持续刷新、捕获掉帧/盲区、人员/动作候选召回与误报、屏幕窗口被遮挡/缩放时行为、目标型号 16GB GPU 在既定分辨率和抽帧策略下的峰值显存、冷/热启动、每事件 p50/p95、事件突发时队列积压和丢弃、10 路端到端提示 p95 是否 ≤15 秒、模型误判与人工复核一致率、Windows/macOS 各自长期运行与自然退出。必须在本机目标环境上对真实候选数据进行授权的离线验收；单帧或一张演示图片不是验收。

最关键的否决点：若需求意味着“每路连续看全帧、任何动作发生后 15 秒内可靠提示”，约 1 万元单机与一张 8GB/16GB 消费级卡在没有十路并发实测前都不应承诺满足。先冻结具体动作定义和可接受漏报率，再做十路、突发负载的短时试点，测不过就降承诺/改采集与触发策略，不通过换成更大模型卡参数来推算容量。
