# Factory Monitor：第 2B 步真实十路闭环与录屏实施计划

> **给 Windows 执行代理：**本轮主目标是可观察的真实十路功能闭环：Seetong 在线画面、真实 YOLO/Qwen、当前屏幕提醒、事件证据和真实功能录屏。不要把全量逐帧账目或 Q1—Q7 全通过设为开始真实功能的前置；它们仍是无人值守长测与正式 V1 的必需 Gate。未经实测不得称任何 Gate 通过。

**目标：**从 `queue-audit-20260923` 独立候选建立唯一的实景副本，在本轮完成 10 路真实人物动作分析、候选和模型结论的可点击提醒、人工纠错，以及一条保留原片的真实 Windows 演示。单路核通和三路检查是同一轮短检查，输入正常即扩到十路，不等待新计划。

**范围：**只判断两类可观察条件：指定区域的可见目标物经过、应值守区域持续无人 300 秒。不得推断盗窃、偷懒或其他意图；不加通用 agent 框架和任意动作类别。本轮不上传真实画面到 GitHub 或交给 coding agents，用户自行登录 Seetong，不索取账号或密码。

**大陆运行硬约束：**Windows 在中国大陆、无 VPN。运行时本地推理优先，不依赖 Codex、GitHub 或国外云在线维持运行；主方案仍为 YOLO11n、独立跟踪、区域/无人规则及本机 Ollama `qwen3-vl:2b-instruct`。`scripts/start-local-model.ps1` 已约定 `127.0.0.1:11435`、`OLLAMA_NO_CLOUD=1`、`models\ollama`；必须保存并读回 `review.endpoint=http://127.0.0.1:11435`，不能填 `/api/chat`，因为代码会自动拼接。`cloud_enabled` 保持 `false`，无付费云 key 需求；初次模型/依赖下载不等于后续推理需要外网。Seetong 的现场联网独立必要，不能一刀切断网而断开摄像头。

**依据与取舍：**两份 Windows 报告中的 111 项回归、单批十路录像及已实现的 EOS 停止屏障，支持继续做有保护的功能集成；真实 YOLO 被排除，故这些结果不能说明已能分析人物动作。清理顺序风险关系到证据保全，用第 3 节的最小保护隔离后即可短期实景运行；超过 512 条的逐帧审计关系到长测故障追溯，移到无人值守前完成。已有事件 SQLite 持久化继续复用，先保证用户能看到分析、提示和可播放证据。

**执行层级：**Sol 负责采集/模型/并发整合；Terra 负责界面、录屏和确定性核验；Luna 归档脱敏结果；Astra 做一次最终关键 Gate。同类修复第二次失败转根因诊断；不逐项开新评审，不关闭用户其他应用，不恢复旧自动化。

旧报告中“本轮不启动 Seetong/模型”的限制只适用于该报告的历史执行，不继承为本轮禁止项；当前授权是开展下述受控实景运行。

## 2. 本地多帧复核、提醒和人工纠错

**文件/入口：**以 Windows 核对后的 Qwen/Ollama 调用点、`gui.handle_runtime_message`、事件存储和通知组件为入口；涉及数据时最小扩展既有 `store.py` SQLite schema/migration，不另建每帧账本平台。

- [ ] **动作：**候选出现即触发当前屏幕黄标和本地系统提醒，保存 `event_id`、`camera_id`、来源、候选时间、证据引用和提醒状态。Ollama Qwen 必须用该事件的实际多帧复核，并将 supported/dismissed/uncertain、模型/提示词版本、延迟和原因写回同一事件；模型结果回来后更新当前屏幕提醒，supported 也须可见提醒，uncertain 须标人工复核，而不是只写日志。
- [ ] **动作：**点击提醒按原始 `event_id` 回读对应 camera、候选、模型结论、可播放证据和人工确认；两事件先后提醒时，点击旧提醒不可打开新事件。人工标签至少有确认、误报、证据不足及原因，修改后读回保留前后值；记录人工发现而系统漏报的事件，避免只从已报警事件计算质量。
- [ ] **用户可见结果：**用户可看到“候选中→支持/不支持/不确定→人工结果”的真实状态链，通知声音和点击目标来自当前 Windows 屏幕。不可用、超时和不确定不可伪装成支持。
- [ ] **最小验证：**对实际物料经过和无人事件各完成一次候选、Qwen 多帧结论、通知点击、证据播放和人工确认；保留 SQLite 回读、GUI 截图/录屏时间点与日志。物料从人工标注的最早可识别帧计时，无人从满足 300 秒条件计时；采集到客户端之前的未知延迟另列。正式门槛为候选 p95 ≤3 秒、首次模型复核 p95 ≤15 秒（含排队和推理）；本轮逐条展示真实耗时，统计同时注明样本量，超时/unknown 保留在分母。若不达标，测量采集、排队、服务实际并发、关键帧、推理和通知，只有证据支持时才做有界并发或关键帧改动，不能降 15 秒、关闭复核或把 watchdog 通知算模型成功。录制与检测已有独立进程，继续复用；扩大队列或声明并发参数不等于服务真的并发。

## 3. 受控实景运行 guard 与停止

**文件/入口：**实际事件接收/容量判断、`evidence.py` 写入、`store.py` 事件状态、`runtime.py` stop 路径和 GUI Stop/关窗入口；先按 Windows 真实代码确认名称。

- [ ] **动作：**在未完成清理事务修复前，以真实程序 guard 隔离风险：独占数据目录、同目录写锁、保留 20 上限不变，并把所有未安全终结/待复核事件的预留计入容量。先在试运行模式统一阻断旧 `_prune_completed` 的自动删除路径，覆盖 start、stop、evidence update、analysis 和 watchdog 入口；重启后仍生效。接收前检查 `completed + outstanding_reservations + new_event_reservation <= 20`、同时录制 ≤10 与磁盘硬门；每个事件只占一个保留名额，状态变更不得重复计算或过早释放。不得只拦第 21 件而忽略在途完成。达到边界、磁盘不足、媒体/DB 写入错误或无法确认写锁时，停止接收新事件，屏幕显式“监测暂停/排空/原因”，保留已有候选和错误；不能靠人工计数或静默丢候选，也不能把暂停期间算作连续覆盖。若这一小 guard 无法安全实现，先修最小清理事务再启动实景；正式 retain-20 循环要求仍保留。若自然事件负载使这个临时保护无法支撑 15—30 分钟功能展示，直接修复有依据的最小可恢复清理事务；不得靠重启清空、挑选安静时段或拼接多段短运行伪装连续运行。
- [ ] **用户可见结果：**容量或写入问题时用户看到暂停而非误报成功；正常 Stop/关窗后显示停止结果和未完成事件，不把 `confirmed` 与录像 `window_complete` 混同。
- [ ] **最小验证：**在独占实景副本做正常停止、事件保存、证据打开、同目录第二启动被锁拒绝，以及小配额/写入故障的可见暂停检查。有限演示只证明本轮留存行为，不能称长期留存通过。

## 5. M1 后仍必须完成的正式 V1 Gate

M1 成功后立即排入无人值守前工作，不得取消：超过 512 的持久逐项账目、审计发送失败、可恢复清理及删除中断矩阵、原参数 Q1—Q7、独立 MP4 像素 oracle 和完整回传包。它们不阻塞本轮真实闭环，却阻塞长期无人值守与正式发布。

V1 原门槛保持：十个不同输入并发时候选 p95 ≤3 秒、模型 p95 ≤15 秒；每类独立调试/测试集至少 50 正例和 100 正常/相似/遮挡反例，候选召回 ≥95%、最终召回 ≥90%，超时/不确定不删分母；正常班次误报 ≤每 camera 每 8 小时 1 次；自动切换完成 100 次放大/恢复且零错绑；先 Windows，再由 Mac 达到相同要求和十路 72 小时。自动 OS 点击在客户端适配/验证完成前保持禁用，手动放大导致的其余九路盲区必须显示；放大 15 秒、回网格至少 30 秒及每路每滚动小时 180 秒盲区预算不变。完整版本不能把此项划为 OPTIONAL。未具十路真实 AI 与第 4 节录屏，绝不可写 M1 PASS；M1 亦不能写 V1 PASS。
