# 现场测试矩阵 Operational Test Plan

> **For agentic workers:** 本文是操作测试计划；收到用户明确“开始”指令前，禁止采集现场画面、安装/启动运行时、接入 NVR、发起付费调用或执行自动化。执行时逐项打勾，不以计划、配置或 GUI 状态替代证据。

**目标：** 在现有本地工程预览上，先完成 Windows 1→3→10 路基线，再按单变量对照定位瓶颈；最终 Windows 与 macOS 的完整验收另行判定。

**现状：** 当前可用基线是单机 WGC/ScreenCaptureKit（目标 OS 实测前均未证明）→ YOLO11n + 每路独立 ByteTrack → 规则候选 → 本地环回 Ollama `qwen3-vl:2b-instruct`。当前服务均只绑定 loopback；云端图片复核关闭。自动 OS 客户端点击/放大/返回没有实现并无条件禁用。

**依据：** `MASTER_PLAN.md`、`docs/ACCEPTANCE.md`、`docs/WINDOWS_HANDOFF_zh.md`、`docs/ARCHITECTURE_UPGRADE_RESEARCH_zh.md`、`STATUS.md`。

## 全局约束与记录

- [ ] 用户明确开始后，由 Root 创建唯一 `RUN_ID`，复制 `scripts/acceptance/session-record.template.json` 到忽略目录 `reports/local/RUN_ID/session-record.json`；每条路线独立一份记录，不改模板。开始前状态必须为 `NOT_STARTED`、`field_gate: FAIL`。
- [ ] 现场原始画面、配置、录像、校准、case manifest、报告只放 `reports/local/RUN_ID/`、`field-data/RUN_ID/` 或 `data/`（均忽略）；不得交给编码代理、远程服务或提交。合成/空白配置仅可用于 UI 检查。
- [ ] 每条记录填写环境（OS/build、客户端与版本、WGC 或 ScreenCaptureKit、窗口像素/缩放、布局版本、十个 camera ID）、提交、配置 hash、模型 digest、磁盘余量和单一变化变量；未测字段写 `null`，不能补成 0 或通过。
- [ ] 计时原点固定：物料为人工标注的最早可辨源帧；离岗为连续“可观察且在班”的缺席阈值到达。排队/切换/入队都不是原点；源到客户端延迟未知时单列 `unknown`。
- [ ] 每事件记录 candidate、review、timeout、unknown、error、证据/明确缺口、人工复核者；超时、未知、无穷/缺失延迟留在分母，不能为 p95 删除。
- [ ] 运行时保存触发前 30 秒、触发后 60 秒，30 秒产预览；先持久化候选再分析。保护 in-flight 证据，记录容量/磁盘限制及可见过载；仅保留最新 20 个**已完成运行时事件**。测试输入素材/标注集与运行时事件列表分开管理；每批事件在循环清理前完成录像读回并记录结果。不得绕过最新 20 条限制做无上限真实事件归档；需要另外保留验收素材时，先明确范围、容量与清理时间。
- [ ] 映射/源心跳异常让对应路为不可判定并重置连续无人计时；复核超时只将该事件转需人工复核，不伪造画面失效，也不拖停独立录像。磁盘压力与采集失败按实际受影响环节记录，保留诊断与缺口；停止软件测试后继续由操作员使用原监控客户端。绝不重启 NVR；磁盘故障只用临时配额/测试卷，禁止填满生产磁盘。

## 共同的开始、停止与回退

**进入条件：** 用户已明确开始，目标电脑的执行会话有本地命令/所需操作权限，目标现场和窗口读取范围明确；Windows 优先。先读取电脑配置并确认至少 50 GiB 可用 SSD，再在本机读取选定窗口做校准；身份/心跳尚未验证时允许本地校准取帧，但规则分析保持暂停。配置保存、重开读回并验证每路 ID/独立心跳后才进入对应路分析。源图不交给编码代理；Computer Use 配置演示使用空白/合成画面。

**记录输出：** `session-record.json`、逐阶段 timing CSV/JSON、每路 coverage/gap log、十事件结果、资源时间序列、可播放证据或明确缺口、人工标注 case manifest、操作员签名的停止原因。正式评价可使用已验证命令：

```bash
.venv/bin/python -m factory_monitor evaluate --input field-data/RUN_ID/held-out-cases.json --output reports/local/RUN_ID/evaluation.json --environment field
```

Windows 等价命令使用 `.venv\Scripts\python.exe`；该 evaluator 的 `field_gate` 仍设计为 `FAIL`，不能取代完整现场证据。

**统一停止/回退：** ID 错绑、未授权来源、隐私边界破坏、证据不可写立即停止受影响分析或新增适配；映射/心跳丢失暂停对应路，继续记录明确缺口。失焦/弹窗须检查是否实际破坏采集或身份，不能无条件伪造中断。诊断中的模型超时/指标不达标记为失败，完成已启动证据录制及预定短测，不能遇到第一个超时就删去剩余九个请求。回退到上一个保存的提交/配置，只关闭本轮新增组件，不动原监控客户端。一次同类失败按证据修复；第二次停止补丁并升级 Sol/Root 诊断。

## 路线 A：现有单机基线（Windows-first）

**目的：** 建立真实客户端下 WGC + YOLO11n + 每路 ByteTrack + 本地 Ollama 的可比较基线；诊断结果不是完整验收。

**前提：** Windows 目标机、获授权窗口、每路独立 heartbeat、至少 50 GiB 可用 SSD 并记录实际峰值；仅 loopback 本地复核。模型不可用时标为 manual-review-required，不视为正常。

- [ ] A1（1 路）：操作员手动选择一个已校准客户端视图；记录 WGC 实际帧、ID、心跳、映射读回；先积累至少 30 秒缓存，再分别验证物料与岗位无人候选、正常相似情况和证据读回。无人规则保持默认五分钟并排除配置休息时段。自动点击保持关闭。
- [ ] A2（3 路）：三路同时运行；逐路验证 ID/heartbeat，并演示一条失效仅使该路不可判定。记录 candidate/review 的逐阶段时间、队列、资源、timeout/unknown/error。
- [ ] A2 附带验证布点图：点位编号、位置、朝向、覆盖区和关联视角与实际相机一致；点击本软件点位后显示的画面/事件属于同一编号。关联视角由操作员选择，不推断跨镜人物身份，不把本软件选中点位当作原客户端已切换。
- [ ] A3（10 路）：十路均独立编号和心跳后运行；用明确标记的本地回放/故障注入检验十个同时候选的工程路径，并另收集现场或经安排的真实并发证据（两种来源分开记录），保存每事件队列及终态。观察一个细节视图时，其他九路按现有主窗口规则记录为 blind/不可观察；自动适配未来启用时，detail 最长 15 秒、回 grid 间隔至少 30 秒、任一摄像头自动盲区不超过滚动一小时 180 秒。当前手动操作仍如实记录所有实际盲区；程序尚不能保证手动操作时限。
- [ ] A4：仅作诊断可做 30 分钟和 2 小时抽样；它们不替代 72 小时、独立样本或误报率验收。若十事件并发未全部在 review 15 秒内完成，明确记录失败分母，禁止以单次成功宣称吞吐达标。

**输出与判定：** `route-A/` 的十路时间线、每事件证据和缺口、p50/p95（含队列）、资源、盲区和 20 条保留状态。candidate 目标 p95 ≤3 秒，review 目标 p95 ≤15 秒；任何未测/未知维持 FAIL。读数未实现时先记录缺项，开始指令到达后由对应执行模型补齐最小计时，不把现有 CLI 当成已提供全部指标。A 后按瓶颈选择：画面信息/盲区走 D；视觉输入冗余走 B；检测重复或后端瓶颈走 C；本机确有资源瓶颈且许可满足才走 E。

## 路线 B：时间戳关键帧 + ROI 对照

**状态：未实现。目的：** 减少本地复核输入，同时保留触发前后时序与带上下文全帧，不用裁剪伪造细节。

**实施前检查：** Terra 先以 A 的冻结提交为对照实现最小的、可回读的关键帧/ROI 记录；Sol 验证运行时落盘和 deadline 锚点；Root 审阅一例完整回放。未通过工程检查不读现场画面。

- [ ] B1：用冻结的调试 case 集、相同模型和单机硬件，先跑全帧基线，再只改变关键帧选择；选定后冻结，再单独比较 ROI 裁剪。每 case 保留原帧、ROI（如使用）、选择理由和帧时间；首次复核不等待 60 秒完整片段，原 15 秒期限不变。
- [ ] B2：人工盲审对比两组候选/最终标签；分别输出 candidate recall、final recall、假警、review p95、输入帧/像素数和队列成本，同一调试事件必须成对用于 A/B 比较，但不得把同一录像的相邻帧分到调试集和独立验收集。

**停止/回退：** 任一原帧缺失、时间错位、ROI 漏掉人工可见关键物料、发现漏检/误报退化则不晋级，保留全部失败并回到 A 全帧基线；单次超时按共同规则处理。B 不改变候选规则、摄像头身份、模型、保留或自动点击状态。

## 路线 C：一次一个计算变量

**状态：未实现。目的：** 先分离检测重复工作，再分离一个硬件/复核后端；不以并发队列冒充算力。

- [ ] C1：仅实现并验证“共享 YOLO 权重/检测”，但十个 ByteTrack 仍独立且不跨摄像头合并。使用冻结 A case 集，输出每阶段耗时、每路 ID 连续性、资源和所有超时。
- [ ] C2：仅在 Windows 上以 C1 或 A 为固定基线，尝试一个 OpenVINO detector；记录导出、驱动、实际设备和相同 case 的端到端差异。无实测不作 UHD 730 或采购结论。
- [ ] C3：仅在 macOS 上以相同可审阅输入尝试一个 MLX-VLM review backend；保持候选端不变，记录冷启动与预热、不同事件与重复帧，不能用缓存重复图外推。

**停止/回退：** ID 串路立即停；候选/最终指标退化或错误/unknown 增长则不晋级并回退。性能改善但仍未满足原 3 秒/15 秒门槛的变体，只能作为明确 FAIL 的诊断候选，不能宣称完成。OpenVINO 与 MLX-VLM 不并行接入；Windows 和 Mac 不互相代替验收。

## 路线 D：独立细节来源（可选）

**状态：未实现。目的：** 比主窗口手工放大更少地牺牲其余九路观察；不建立 RTSP/NVR 前提，也不宣称获得更高原始分辨率。

**前提：** 客户端可提供独立细节窗口，或 NVR 有已授权的只读本地接口；需先实现新 adapter、校验源身份/时间/每路映射，并在之后获得明确授权。需分别确认读取端的访问范围；独立窗口可保持本机，NVR 网络读取不得自动扩展为远程模型服务。

- [ ] D1：对 A 的一个固定事件，比较主窗口手工 detail 与独立来源：记录其余九路 coverage、detail 时间、源时钟/客户端时钟、证据完整性和人工复核结果。
- [ ] D2：若 NVR 适配获准，验证只读、断连、权限拒绝和时钟不确定的失败路径；无授权不尝试连接。

**停止/回退：** 源身份/时钟/权限无法读回、任一路映射不明或证据断裂，停用 adapter，回到 A 的手动客户端路径。不得自动切换、PTZ 或跨视图身份推断。

## 路线 E：双机完整事件复核（可选）

**状态：未实现。目的：** 将一次模型复核任务整体交给第二台经许可的本地复核端；不是 PD 模型分片，也不拆 prefill/decode。候选和本轮关键帧先落盘即发送，60 秒完整录像仍在原机异步生成，绝不等完整录像后才开始 15 秒首次复核。

**前提：** 新 adapter 已实现和测试；之后用户明确允许两机网络、列明双方地址/防火墙、时钟同步方法、数据最小化、断网回退和本地留存。不得创建持续远程代理/监控自动化；不传生产画面到云。

- [ ] E1：仅用一条已授权且候选/关键帧已落盘的事件进行端到端交接；记录发送/接收 hash、两机时钟不确定性、队列、review 终态与本机 fallback。
- [ ] E2：网络断开、目标超时和接收拒绝时，确认事件留在原机且为 manual-review-required；无静默丢失、无自动重传到未知端。

**停止/回退：** 许可、时钟、hash、网络隔离或本地隐私任何一项不成立，关闭 E adapter、将未发/未完成任务明确记为需人工复核，不删除证据；本机有能力时回退 A review，原 deadline 不重置，防止双端重复通知。E 不改变候选判定、告警或客户端控制。

## 数据集、模型责任与正式验收

- [ ] 数据分为调试集与独立 held-out 测试集：每个集合中每类（`material_candidate`、`station_absence`）至少 50 正、100 负/混淆例，candidate/final 分别评分。样本按独立录像/事件分组，不能用相邻帧分割或从调参录像复用；来源、标签者、证据/缺口与 reviewer 写入 case manifest。
- [ ] Root/Astra 负责 Gate、记录一致性和最终人工审阅；Terra 负责确定性模块、配置与常规测试；Sol 负责共享跟踪整合、采集/双机适配、运行时、模型/队列、容量和故障诊断。Luna 仅可做不含生产画面的本地文档/提取辅助。任何 tier 都不得在缺少必要证据时把 `FAIL` 改为 `PASS`。
- [ ] 最终质量门槛：candidate recall ≥95%，final recall ≥90%，candidate p95 ≤3 秒，首次 review p95 ≤15 秒（含排队），最终误报 ≤每摄像头每 8 小时 1 次，并列候选数量/人工负担。没有独立实测证据不得判定 PASS。
- [ ] 完整验收单独执行：真实 Windows 后再真实 macOS，客户端专用安全自动适配完成并通过工程检查后，各自 100 次真实客户端自动 detail/grid 周期（零 ID 错绑，含缩放、失焦、弹窗、重启故障）与独立 72 小时十路运行；记录崩溃、冻结、超时、磁盘、重启、留存、缺口、十同时事件和正常班次每摄像头 8 小时假警。
- [ ] 分别验证遮挡、最小化、锁屏、黑屏和客户端重启的实际采集行为；不得只凭 API 名称断言可后台读取。检查重启后待复核/录制任务的明确恢复结果、20 条循环清理以及在途证据保护。读写故障只在专用测试目录/配额环境注入，不破坏已留存原始样本。

## 条件旁路 H：开发成本影子研究

**状态：未实现且非现场路线。** SoL-Pi 只借鉴可回读 observation/cost 记账理念，不安装、不接 reducer、不传视频/事件/日志。Jev 名称、具体技能、数据出境、预算和 provider 未确认前，不做外部请求、付费调用或生成图片。

- [ ] 若上述事项未来明确，先只用合成或脱敏文本，影子比较固定规则、已有低成本模型和已确认的 Jev：路由错误、漏升级、延迟、实际调用与返工成本。
- [ ] 影子结果不可丢事件、改告警、驱动点击或改变 A–E Gate；外部 provider 未逐项确认则该路线保持 `NOT_STARTED`。

## 执行交接

本计划已就绪，等待用户的明确开始指令与在线摄像头可用。开始后先完成环境预检和本地校准，再执行 A1，按记录的可见失败选择唯一的下一变量；不要同时启动 B–E，也不要把 30 分钟/2 小时抽样写成正式验收。
